SKY CARS PRIVATE LAB — HOSTINGER DOMAIN BINDING
===============================================

The application already contains these routes:
  /lab
  /lab/login
  /lab/apps/[slug]
  /api/lab/*

WORKING FALLBACK
----------------
Use:
  https://skyshcars.com/lab

WHY lab.skyshcars.com CAN STILL FAIL
------------------------------------
A 502 Bad Gateway or ERR_CONNECTION_CLOSED for lab.skyshcars.com happens before the Next.js route is served. That indicates Hostinger hostname/DNS/proxy/SSL binding, not a missing /lab route.

RECOMMENDED HOSTINGER SETUP
---------------------------
Do NOT rely on a static /public_html/lab folder for this Next.js route.
Bind the hostname lab.skyshcars.com to the SAME Node.js application that serves skyshcars.com, using Hostinger's Node.js application domain/custom-domain connection workflow.

Checklist:
1. In Hostinger, open the deployed Node.js application for skyshcars.com.
2. Find its Domain / Custom domain / Connect domain control.
3. Add lab.skyshcars.com to that SAME application.
4. Confirm DNS for host 'lab' resolves according to Hostinger's required target.
5. Confirm SSL is issued/active for lab.skyshcars.com.
6. Restart/redeploy the application if Hostinger requests it.
7. Open https://lab.skyshcars.com/ and confirm it reaches the Lab login.

If Hostinger's generic Subdomains screen only creates a physical public_html folder, that does not automatically proxy a Node.js route and is not sufficient by itself.
